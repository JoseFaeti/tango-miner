# Coding guidelines

- Resist unnecessary complexity. Keep solutions simple and follow applicable best practices and existing project conventions.
- Aim for small, cohesive files, ideally 100–300 lines of code. Treat this as a guideline, not a reason to split cohesive code or make unrelated changes.
- Make code modular where it improves clarity and reuse, without adding unnecessary abstractions.
- Store repeated property accesses in local variables when appropriate, while preserving behavior if values can change.
- Organize related code clearly within files and place files coherently within folders.
- Use comments sparingly to explain why code exists or a decision was made, when that is not clear from the code itself. Avoid comments that merely restate what the code does.
